## Allowed activities

- SQL Injection (SQLi)
- Cross-Site Scripting (XSS)
- Remote Code Execution (RCE)
- Insecure Direct Object Reference (IDOR)
- 수평·수직 권한 상승
- 인증 우회 및 취약한 인증
- 실질적 보안 영향이 있는 Business Logic Errors
- Local files access and manipulation (LFI, RFI, XXE, SSRF, XSPA)
- 실질적 보안 영향이 있는 CORS
- 실질적 보안 영향이 있는 CSRF
- Open Redirect
- 조직 통제 자산에서 노출된 비밀값·자격 증명·민감 정보
- 다른 사용자에게 영향을 주는 AI 모델 변경
- 다른 사용자의 결과에 영향을 주는 유효 입력 교란
- 다른 사용자의 기록에 접근하는 기록 보호·삭제 메커니즘 우회
- AI 모델 또는 데이터의 아키텍처·학습 코드·데이터·하이퍼파라미터 변조를 통한 오염

## Prohibited activities

- DoS 공격
- 서비스 저하 또는 중단을 유발할 수 있는 테스트
- 대량 네트워크 트래픽을 발생시키는 자동화 스캐너·도구 사용
- 사용자 데이터·파일의 유출·조작·파괴
- 애플리케이션·서버 파일 복사 및 공개
- 취약점의 전체·일부 공개
- Social engineering of staff or contractors
- 무차별 대입 또는 CAPTCHA 문제
- 고엔트로피 UUID·토큰 등의 추측·예측에 의존하는 취약점
- 정상 공개 공유 링크를 사용한 인증 없는 리소스 접근

## Submission requirements

- 최초 제보자여야 한다.
- 유효한 보고서는 명확한 취약점 설명, 악용 방법, 보안 영향, 수정 조언을 포함해야 한다.
- 악용 수행과 최종 영향을 보이는 스크린샷 PoC를 포함해야 한다.
- 필요 시 코드 조각·페이로드·명령 등을 포함한 완전한 재현 절차를 제공해야 한다.
- 발견 방법과 취약한 엔드포인트 또는 자산을 식별한 과정을 설명해야 한다.
- 동일 취약점을 여러 번 발견한 경우 보고서 하나만 생성하고 댓글을 사용해야 한다.
- 제보 제출에는 hunter 계정 로그인이 필요하다.

## Operational constraints

- 테스트용 계정 생성 시 YWH 별칭(@yeswehack.ninja)만 사용해야 한다.
- 기존 계정을 가능한 재사용하고 불필요한 계정을 만들지 말아야 한다.
- kChat 또는 Mail 지원 티켓 등 지원 채널을 집중적으로 테스트해서는 안 된다.
- 모든 요청의 User-Agent는 \`Infomaniak-YWH-Bugbounty\`로 설정해야 한다.
- 프로덕션에 치명적일 수 있는 테스트는 사전에 팀에 연락해야 한다.
- 대부분 제품은 무료로 테스트 가능하며, 그렇지 않은 경우 합리적 가격으로 구독할 수 있고 테스트 목적으로 자가 등록할 수 있다.

## Safe harbor

명시되지 않음.

## Ambiguities requiring review

- 안전 항구(safe harbor) 조항은 명시되지 않았다.
- 자산 목록에는 \`\*.infomaniak.com\`이 포함되지만, 별도 제외 목록의 특정 자산·경로 및 목록에 없는 자산은 제외된다.
- OpenStack 제품에서 리소스 생성 및 구성 오류·비보호 데이터 탐색은 언급되지만 Horizon의 XSS는 제외된다고 명시되어 있다.
- Business Logic Error 및 Broken Access Control은 PII·고객/기밀 데이터 유출 또는 중대한 사업·재무 영향 같은 심각 사례만 보상 대상이라는 추가 제한이 있다.
