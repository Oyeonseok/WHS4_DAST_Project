# 실제 버그바운티 프로그램 실행

AI DAST의 실제 프로그램 실행은 현재 게시된 프로그램 정책을 먼저 수집하고 운영자가
원문과 대조해 승인한 뒤 시작한다. 공개 프로그램 목록에 있다는 사실만으로 자동화 테스트가
허용되는 것은 아니다. 자동 스캐너 금지, 사전 연락, 테스트 계정 도메인, 식별 헤더,
요청 속도 같은 조건은 승인 Scope의 실행 요구 사항으로 보존된다. 지원할 수 없는 필수
조건이 있으면 대시보드는 스캔 시작을 차단한다.

## 대시보드 실행 순서

1. **스코프 / 프로그램**에서 테스트할 정확한 프로그램 상세 페이지 URL을 등록한다.
2. **스코프 수집**을 시작한다. 로그인이나 MFA가 필요하면 열린 전용 브라우저에서 직접
   완료하고 대시보드에서 계속한다.
3. 인스코프와 아웃오브스코프 자산, 금지 행위, 자동화 허용 여부, 요청 제한, 필수 헤더와
   사전 연락 조건을 원문과 대조한다. 내용이 빠졌거나 애매하면 승인하지 않고 다시 수집한다.
4. 검토자 이름을 입력하고 **승인 · 스코프 확정**을 선택한다. 승인 파일은 수집한 원문과
   해시로 결합되며 이후 정책이 바뀌면 새 Scope 개정본을 수집해야 한다.
5. **새 스캔**에서 승인 Scope와 **버그바운티 안전** 프로필을 선택한다.
6. 자산 하나만 선택한다. `*.example.com` 같은 와일드카드는 실제로 열어 볼 승인 호스트의
   정확한 HTTPS 시작 URL을 입력한다. 로그인 후 화면부터 확인해야 하면 해당 경로를 시작
   URL로 입력하고 **런타임 브라우저 열기**를 선택한다.
7. 정책이 요구하는 사용자명, 이메일, 식별 헤더 값과 확인 항목을 채운다. 표시된 정책
   차단 사유가 하나라도 남으면 실행하지 않는다.
8. 테스트 권한과 사전 조건 충족 확인을 선택한 뒤 스캔을 시작한다.

## 버그바운티 안전 프로필

이 프로필은 요청 속도를 초당 0.2회, 동시 실행을 1개, 전체 요청 예산을 300회, 탐색 깊이를
2로 제한한다. 프로그램 정책이 더 낮은 제한을 선언하면 그 값이 우선한다. 프로그램 정책이
더 높은 속도를 허용해도 이 프로필의 초당 0.2회 상한은 유지된다.

일반 단어 목록을 경로에 대입하는 ffuf 탐색은 꺼진다. 정찰은 시작 URL의 응답, 링크와 폼,
브라우저 네트워크 기록, 공개 JavaScript와 API 문서처럼 실제 블랙박스 실행 중 관측한 정보로
진행한다. Recon Wiki나 공개 정답 목록은 실행 후 누락 비교에만 사용하며 정찰 또는 공격
입력으로 주입하지 않는다.

300회 예산은 Recon, Attack, Validation이 공유한다. 먼저 자산 하나의 좁은 시작 URL로
완주해 보고서 초안까지 생성되는지 확인한다. 다른 자산은 별도 스캔으로 실행한다. 더 넓은
프로필은 프로그램 원문이 해당 자동화와 속도를 명시적으로 허용하고 운영자가 그 근거를
확인한 경우에만 선택한다.

## 결과 검토

Attack 결과는 제출 가능한 취약점 확정이 아니라 검증 후보다. Validation에서 대상 응답과
재현 증거, 영향, 정책 적격성을 확인한 결과만 보고서에 포함한다. 보고서는 로컬 초안으로
남으며 플랫폼에 자동 제출되지 않는다. 운영자는 재현 절차가 범위 안에 있는지, 다른 사용자
데이터를 포함하지 않는지, 프로그램별 제출 형식을 충족하는지 확인한 뒤 직접 제출한다.

프로그램이 자동화 테스트를 금지하면 해당 프로그램에는 AI DAST를 실행하지 않는다. 정책이
허용 여부를 명확히 말하지 않거나 외부 참조 페이지를 수집하지 못했다면 프로그램 운영자에게
확인하거나 수동 검토가 끝날 때까지 실행을 보류한다.
