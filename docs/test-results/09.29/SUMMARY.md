# 09.29 실험 결과 요약

## Scope 생성 단계의 정책 준비 및 승인 버전 재수집

### 실험 목적과 변경

스캔 시작 시 연결된 정책 문서의 근거가 없다는 이유로 중단되는 문제를 해결하기 위해 정책 준비를 Scope 생성·재수집 단계로 옮겼다. AI는 실제 관찰한 링크와 해당 화면의 원문을 근거로 관련 문서를 선택하고, 애플리케이션은 공개 HTTPS 문서를 제한된 전송으로 수집한다. 필수 요청 헤더, 요청 제한, 제외 규칙과 보고·공개 의무를 최종 분석해 Scope.json/Scope.md에 저장한다. 스캔은 선택한 승인 버전의 저장된 실행 규칙을 사용한다.

정책의 의미와 적용 단계는 AI가 판단한다. 코드에서는 관찰된 링크 ID, 정확한 출처 인용, 수집 제한, 원래 프로그램의 자산 권한을 검증한다. 확인하지 못한 테스트 관련 문서는 보류 근거로 남긴다. 보고·공개 지침 수집 실패만으로 테스트 차단을 자동 추가하지 않으며, 특정 오류 문구를 지워 우회하는 처리는 없다.

기존 Collect again의 승인본 반환 동작을 명시적 재수집으로 수정했다. 새 초안은 별도 revisions/<scopejob_id>에 저장하고 기존 검토·승인을 거친다. 선택한 버전은 대시보드, 워커, 카탈로그, CLI 실행까지 전달된다. 재수집이 진행 중이거나 거절·실패하더라도 이전 승인본은 사용할 수 있다. 동시 재수집과 경로 검증도 추가했다.

본문뿐 아니라 HTTP 헤더·청크 전송 데이터·리다이렉트 응답까지 크기 제한을 적용하는 보완을 테스트했다. 첫 화면의 링크 128개가 이후 화면의 링크 수집을 막는 경우도 공개/인증 화면에서 실패를 재현하고 수정했다. 저장된 정책을 다시 AI 해석 없이 사용하는 동작과 승인 버전의 실제 CLI 선택을 로컬 테스트로 확인했다.

실제 Neon 재수집·공격·외부 모델 호출은 수행하지 않았다. 백엔드 재시작과 운영 DB 변경도 하지 않았다. 기존 Neon 승인본에 새 정책을 적용하려면 변경 코드로 서버를 실행한 후 Collect again → 검토·승인 → 새 Scope 선택으로 진행해야 한다. 수집되지 않은 대상 리소스의 제외 규칙 판단은 기존 근거 기반 보류 동작을 유지한다.

## 애매한 정책의 주의사항 분리와 공통 Agent 전달

### 실험 목적과 변경

참조 문서의 수집 실패나 정책 해석의 불확실성만으로 Neon 등의 전체 스캔이 중단되는 문제를 다뤘다. 앞선 실험에서 테스트 적용 여부를 알 수 없는 참조를 일괄 보류했던 동작을 변경했다. AI는 근거가 있는 필수 조건과 애매한 주의사항을 구분하고, 확인하지 못한 문맥은 대시보드의 접힌 주의사항에 표시한다. 명시적 권한, 필수 식별 헤더, 요청 제한, 제외 규칙 및 충족되지 않은 필수 조건은 계속 강제한다. 특정 서비스나 오류 문구를 필터링해 차단을 지우는 방식은 사용하지 않는다.

공통 `aidast-policy/SKILL.md`와 실제 대상별 정책 입력을 Recon·Attack·Chaining·Validation·PoC·영향 검증에 전달한다. 실행 Agent는 허용된 작업을 계속하면서 애매한 개별 동작을 건너뛰고 이유를 기록한다. 개인정보 발견 시 중지 등의 조건도 함께 전달한다. Blind Validation에는 공격 주장과 분리한 정책 문맥을 제공하며, 재개된 검증에는 현재 대상의 주의사항만 전달한다. 수집·해석 단계에는 아직 생성되지 않은 승인 파일을 요구하지 않는다.

참조 선택에는 필수·보조·불확실 관계를 저장하고 필수 참조를 먼저 수집한다. 같은 문서의 URL fragment만 다른 경우 재수집하지 않으며 query가 다른 URL은 별개로 처리한다. 기존 승인본은 수정하지 않고 버전4 해석 캐시에 새 검토를 저장한다. 오래된 승인본을 선택하면 한 번 재해석한 뒤 주의사항만 있는 스캔은 시작할 수 있다. 동의 항목은 추가하지 않는다.

긴 인용문이 여러 위치에 중복돼 Recon의 입력 한도를 넘는 실패도 재현했다. 실행용 표현에는 원문을 한 번 전달하고 정확한 인용 위치와 해시를 연결해 모든 주의사항·제약·승인 문맥을 보존한다. 원본 Scope와 실제 요청 정책 생성에 사용하는 원문은 유지한다. 중복을 제거한 뒤에도 내용 자체가250000자를 넘으면 기존 한도로 명시적으로 거절한다.

### 검증 및 정량적 성과

| 항목 | 결과 |
|---|---|
| 긴 정책 실패 재현 | 원문11778자, 미수집 참조8개, 주의사항8개, 강제 차단0개 |
| Recon 계획 입력 | 289559자 →29967자, 약89.65% 감소; 두 어댑터의 실제 계획 입력 경계 통과 |

| 기존 승인·결과 자료 | 554개 해시 비교, 변경0개 |

전체 Python 회귀는 동시에 진행 중인 별도 Recon 수정과 구분하기 위해 작업 시작 시의 소스·테스트와 이번 변경을 합친 고정 사본에서 실행했다. 별도 Recon 테스트4개는 변경 전 사본에서도 동일하게 실패했다(7개 통과 /2.54초). 해당 작업은 수정하지 않았으며, 현재 작업 폴더의 다른 Recon 변경과의 통합 검증 결과로 해석하지 않는다. 검증 사본에서 빠졌던 보조 도구·패키지 리소스·고정 실험 자료를 보완한 과정과 초기 실패 로그도 기록했다.

실제 Neon 공격, 외부 모델 호출, 백엔드 재시작은 수행하지 않았다. 로컬 검증은 정책 전달과 실행 조건을 확인하며 AI가 실제 공격 중 주의사항을 준수했음을 증명하지는 않는다. 적용은 새 코드로 서버를 재시작하고 대시보드를 새로고침해 기존 Scope의 정책 검토를 완료하면 된다. 주의사항만으로 시작을 막지 않으며 필수 조건은 별도로 충족해야 한다.
