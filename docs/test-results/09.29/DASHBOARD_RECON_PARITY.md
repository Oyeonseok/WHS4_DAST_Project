# 웹 대시보드 Recon 개선 및 검증

## 문제와 원인

기존 Juice Shop 대시보드 실행은 URL 발견 활동 12건, DB 엔드포인트 17개였지만 정적 리소스를 제외한 서비스 경로 13개 중 실제 HTTP 응답이 연결된 경로는 `/` 하나였다.

웹 CLI는 공유 요청 제한을 바인딩하지만 과거 일부 직접 실행 실험은 공유 governor 없이 실행됐다. API broker와 정책 프록시가 같은 요청의 동시성·예산을 두 번 예약해 동시성 1에서 자기 요청을 차단하는 현상을 재현했다. 브라우저의 동시 요청도 대기 없이 거절됐으며, 웹 실행기는 ffuf 워드리스트를 전달하지 않았다. 당시 차단 29건 모두의 개별 원인을 확정할 로그는 없다.

## 반영한 내용

| 항목 | 구현과 검증 |
|---|---|
| 웹 실행 경로 | 저장소 공통 워드리스트와 루트별 탐색 시간을 CLI에 전달한다. 프록시 전송의 공유 예산은 프록시가 한 번만 예약하며 broker의 Scope·헤더·제외 조건 검사는 유지한다. 동시성 및 주기별 한도는 비동기로 기다리고 영구 예산 초과는 거절한다. |
| ffuf 뒤 재분석 | 최초 분석 상태를 유지하고 ffuf 뒤 최대 3회 추가 분석한다. 새 HTML·JS·JSON과 기존 서비스 코드를 연결한다. 전체 URL·본문 해시·인증 조건으로 요청과 파싱 결과를 재사용한다. 새 스크립트의 한도는 이미 파싱한 모듈과 분리한다. 인라인 변경·삭제·이전 버전으로의 복귀도 처리한다. |
| 캡처 읽기 | 파일 앞 2,000행·8MB 제한 대신 마지막 읽은 위치부터 완성된 새 행을 읽는다. 부분 행은 다음 조회까지 보류하고 큰 완성 행은 건너뛴다. 정상 근거 최대 120건/7MB와 접근 제한 근거 최대 30건/1MB를 나눠 보관한다. 404·5xx 잡음이 정상 문서를 밀어내지 않는다. 보관 한도에 따른 제거 수는 진단에 남긴다. |
| 상세 GET 20개 | 출처별 서로 다른 경로 템플릿을 먼저 순환하고 이후 추가 ID·쿼리를 검증한다. 한도를 초과한 실제 값 기반 후보는 `candidate` 및 `detail_probe_limit` 사유로 보존한다. 한도·경로 수·미검증 후보 수를 대시보드 활동에 전달한다. |
| 동적 source query | 고정 경로와 실제 관측한 쿼리·응답을 JS 관계에 연결한다. 고정 쿼리 값, 중복 키, 추가·누락 조건, 출처 및 인증 조건을 검사한다. 전체 URL별 응답을 구별하고 상세 경로의 배분 단위만 템플릿으로 묶는다. |
| ffuf 범위와 시간 | 정적 파일을 제외한 관측 경로에서 최대 3개의 기본 루트를 결정하고 AI 제안을 추가한다. AI 선택 실패 시 기본 루트를 사용한다. CLI·웹·ffuf의 0초는 시간 제한 없음이며 subprocess timeout도 `None`이다. 계획 요청 수와 실제 예산의 차이를 표시한다. |

정책 프록시가 추가한 필수 식별 헤더를 포함한 실제 요청 조건으로 캡처의 인증 해시를 비교한다. 이전 익명 캡처의 누락된 인증 메타데이터도 익명 조건에서만 사용할 수 있다. 수집된 응답은 다른 인증 조건으로 재사용하지 않는다.

## 실제 로컬 검증

### AI 태깅 진행률

태깅은 배치가 끝날 때마다 처리 관측 수, 전체 관측 수, 완료 배치 수와 실패 수를
`agent.work` 이벤트로 기록한다. 대시보드는 `AI 태깅 · 50% · 처리 25/50건 · 배치 1/2 완료`
형태로 표시하며 Recon 진행률의 태깅 구간도 76~88%에서 갱신한다. 모델이 한 배치를
처리하는 동안에는 마지막 완료 수를 유지한다.

이전 실행기가 시작 이벤트만 기록한 경우에는 저장된 태깅 결과로 진행률을 복원한다.
관측당 여러 분류는 한 건으로 세고 다른 스캔의 결과는 제외한다. 같은 결과를
재조회해도 로그를 중복 기록하지 않으며 태깅 종료·실패, 검토·내보내기 단계에는
태깅 진행 이벤트를 추가하지 않는다. 태깅 완료 시 정찰 에이전트의 진행 표시도 종료한다.

실제 이벤트와 스냅샷의 메타데이터 검증, 한국어·영어 표시, 배치별 CLI 이벤트,
기존 실행기 복원 및 실패 상태 보존을 회귀 테스트로 확인했다. 로컬 대시보드 실행의
관측 393건은 모두 태깅을 마치고 공격 단계로 넘어갔다.

### 승인된 Juice Shop Recon 비교

기존 실행: `result/Runs/lab-aidast-invalid/neon-policy-juice-shop/scan_60294a8add7f4e3faa6d1dd5a75315ba/Recon.db`.

개선 작업 중 비교 실행: `result/test-runs/09.29/dashboard-juice-governed/`. 기존 대상 `http://127.0.0.1:3001/`의 승인된 정책을 재사용했다. 예산 500회, 10rps, 동시성 1을 유지하고 폼 제출은 비활성화했다. 모델 호출은 오프라인 스텁으로 대체했으며 HTTP probe·origin·endpoint Recon만 실행했다. ffuf 시간은 루트당 15초로 제한했다.

| 지표 | 기존 대시보드 실행 | 개선 비교 실행 |
|---|---:|---:|
| DB 엔드포인트 전체 | 17 | 58 |
| 정적 리소스 등을 제외한 서비스 경로 | 13 | 48 |
| 실제 HTTP 응답이 연결된 서비스 경로 | 1 | 48 |
| 2xx 응답이 확인된 서비스 경로 | 1 | 41 |

개선 비교 실행 시간은 326.8초였다. 공유 governor 차감은 400회, DB에 적재된 HTTP transaction은 368건이었다. 상세 GET은 총 20개 한도에 도달했고 마지막 추가 분석의 미검증 후보는 8개였다. ffuf는 한 루트를 실행한 후 활성 요청 예산에 도달해 나머지 루트를 생략했다. 따라서 전체 워드리스트 완료나 과거 58·22 실험과 동일한 수집 조건을 재현했다고 볼 수 없다. 각 숫자는 정규화된 경로 기준이며 쿼리별 관측 근거는 별도로 보존한다.

비교 근거는 `comparison.json`, `summary.json`, `Recon.db`, `Surface.json`, `diagnostics.jsonl`에 남겼다. 후속 캐시·루트 fallback 보강의 최종 코드는 아래 회귀 검사와 독립 통합 검사로 확인했다.

### 실제 프록시·브라우저·ffuf 통합 검사

임시 루프백 HTTP 서버에서 필수 식별 헤더를 요구하도록 구성하고 실제 mitmproxy, Chromium, ffuf를 연결했다. `NO_PROXY`에 localhost를 넣어도 broker가 프록시를 거치도록 검사했다.

| 지표 | 결과 |
|---|---:|
| API broker 첫 요청 | HTTP 200, 공유 예산 1회 차감 |
| 병렬 브라우저 GET 4개 | 모두 HTTP 200 |
| 최대 실제 서버 동시 처리 | 1 |
| 실제 서버 요청 / governor 차감 | 19 / 19 |
| 미완료 permit | 0 |
| ffuf 뒤 HTML → script → 실제 API 쿼리 | 발견 성공 |

최종 통합 근거: `result/test-runs/09.29/dashboard-recon-parity-final/summary.json`.

## 적용 범위와 남는 제한

새 대시보드 빌드와 실행 옵션을 로컬 서버에 반영했다. 진행 중인 대시보드 스캔이 없는 상태에서 서버를 재시작하고 API schema 및 실제 제공되는 JS에서 새 옵션을 확인했다. 새 실행부터 적용되며 이전 결과의 URL 수는 자동 변경되지 않는다.

0초는 ffuf 시간 제한만 해제한다. Scope 제한, 공유 요청 예산, 실행 프로필과 브라우저용 예약 예산은 계속 적용한다. 4,752개 단어 × 3개 루트는 최소 14,256회이며 10rps에서도 약 23분 46초가 필요하다. 500회 예산 또는 루트당 150초로 전체 탐색을 완료할 수 없다. 현재 웹 프로필의 요청 예산 상한은 safe-recon 500회, focused-discovery 2,000회이므로 시간만 늘려 전체 규모를 소화할 수는 없다.

커밋 전 최종 검증: Python Recon·정책·대시보드 1,186개 테스트 및 77개 subtest 통과,
UI 112개 테스트 통과, production build 및 `uv lock --check --offline` 성공.
실제 프록시 통합 검사는 위의 최종 통합 산출물에서 통과했다.

전체 저장소 검사에서는 삭제된 legacy `result/Scope/lab-aidast-invalid/juice-shop/Scope.md`를
참조하는 Validation 실험 테스트 7개가 실패했다. 또한 비동기 프록시 호출과 기본 ffuf 루트
추가를 반영하지 못한 테스트 26개를 수정했으며 해당 파일들의 재검사 63개 및 위의
관련 전체 검사에서 통과했다. legacy Scope에 의존하는 Validation 실험의 통과는 확인하지 못했다.
