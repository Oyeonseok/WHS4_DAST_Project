# 자동 PoC 증거 재생 영상

검사를 통과한 제출 보고서는 저장된 정제 증거를 설명하는 WebM 영상을 만들 수 있습니다. `evidence_replay` 영상에는 **EVIDENCE REPLAY · STORED MASKED EVIDENCE**와 **Not live reproduction footage** 표시가 항상 나타납니다. 대상에 접속하거나 새로운 요청을 재현하지 않으며, 실제 공격 장면이나 원시 화면 녹화를 주장하지 않습니다.

## 생성 및 제출

대시보드에서 생성한 영상을 미리 보거나, 영상 포함 옵션으로 제출 ZIP을 내보냅니다. 별도 수동 승인 절차 없이 현재 보고서의 자동 검사를 적용합니다. CLI에서 영상 포함을 선택하려면:

```bash
aidast report export result/ReportRun/<scan_id>/<case_id>/Report.db \
  --requirements program-requirements.json --poc --output submission-with-video.zip
```

`--poc`를 생략하면 기존 텍스트 전용 내보내기를 사용합니다. 텍스트 전용 내보내기는 브라우저나 코덱에 의존하지 않습니다.

영상 ZIP에는 기존 보고서·증거 파일과 함께 다음 파일이 추가됩니다. 기존 보고서·증거 파일의 내용은 바뀌지 않으며 manifest에는 추가 파일의 크기와 SHA-256이 기록됩니다.

| 파일 | 내용 |
| --- | --- |
| `PoC/Video.webm` | VP8, 1280×720, 초당 2프레임 증거 재생 영상 |
| `PoC/Storyboard.json` | 마스킹된 화면별 본문, 증거 식별자, 원본·정제 증거 해시 |
| `PoC/Metadata.json` | 보고서 리비전, 모드, 영상·스토리보드·렌더링 프레임 해시, 길이와 크기 |

## API

```text
GET  /api/v1/reports/{report_id}/poc
POST /api/v1/reports/{report_id}/poc?revision={revision_sha256}
GET  /api/v1/reports/{report_id}/poc/video?revision={revision_sha256}
GET  /api/v1/reports/{report_id}/export?revision={revision_sha256}&include_poc=true
```

POST는 same-origin 요청이어야 하며 revision은 생략할 수 있습니다. GET 영상은 revision을 필수로 받고 검증된 캐시만 읽습니다. GET 영상 조회는 새 영상을 생성하지 않습니다. 상태는 `missing`, `ready`, `stale`, `blocked`이며 정상 캐시의 경우 길이·크기·해시·리비전도 제공합니다. 잘못된 revision 형식은 422, 자동 검사·리비전·미디어 검증 실패는 409입니다. 오류에 원본 경로나 브라우저·코덱 stderr를 노출하지 않습니다.

## 제한 및 검증

영상 본문은 `inspect_report`가 반환하는 마스킹된 정상 보고서 뷰만 사용합니다. 제목·요약, 대상과 기대/관찰 비교, 저장된 재현 단계, 모든 증거 메타데이터, 보고된 영향을 페이지로 나눕니다. 각 페이지는 5초이며 최대 12페이지입니다. 전체 증거를 이 한도에 담을 수 없으면 잘라내지 않고 생성을 차단합니다. 넓은 문자 등으로 실제 화면에서 본문이 잘리거나 출처 표시와 겹쳐도 차단합니다.

설치된 Playwright Chromium과 시스템 FFmpeg 또는 Playwright에 포함된 FFmpeg를 사용합니다. HTML을 이스케이프하고 네트워크·서비스 워커·페이지 스크립트를 차단한 브라우저에서 JPEG를 생성한 뒤 VP8 WebM으로 인코딩합니다. 전체 디코딩으로 프레임 수, 길이와 실제 화면 크기를 검사합니다. 브라우저 또는 필요한 코덱이 없거나 생성 시간이 90초를 넘으면 차단합니다. 새 패키지 설치는 수행하지 않습니다.

현재 영상 생성의 프로세스 간 잠금은 POSIX `fcntl`을 사용합니다. 이 모듈이 없는 Windows에서는 영상 생성을 차단하며, 대시보드 시작과 기존 텍스트 ZIP 내보내기는 계속 사용할 수 있습니다.

영상은 최대 10,000,000바이트, 영상 메타데이터는 최대 256,000바이트입니다. 기존 텍스트 패키지의 8,000,000바이트 제한을 유지하고 영상 포함 시 추가 예산만 허용합니다.

캐시는 보고서 디렉터리의 비공개 `.poc-video` 아래에 리비전별로 원자적으로 저장합니다. 파일 해시, 별도 무결성 목록, 엄격한 메타데이터 구조와 현재 보고서에서 다시 만든 스토리보드를 대조합니다. 심볼릭 링크와 손상된 캐시는 사용할 수 없습니다. 손상된 현재 리비전 캐시는 자동으로 덮어쓰지 않습니다. 원인을 확인하고 해당 비공개 캐시를 제거한 후 다시 생성할 수 있습니다. 보고서·Validation·프로그램 지침이 바뀌면 이전 영상을 사용하지 않습니다. 생성과 조회, 내보내기 완료 전에 출처를 다시 검사합니다.

해시는 로컬 캐시의 무결성 확인용이며 외부 공증 서명이 아닙니다. 원래 보고서와 증거는 수정하지 않습니다. 기존 패턴 마스킹의 한계도 동일하게 적용되므로, 이름이 없는 임의의 비밀값을 모두 탐지한다고 보장하지 않습니다. 각 플랫폼·프로그램의 첨부 정책은 제출 시 따로 확인해야 합니다.
