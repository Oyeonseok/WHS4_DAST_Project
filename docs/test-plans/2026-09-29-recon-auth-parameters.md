# Recon 인증·관측 값 연결 개선

사용자 승인 범위: 기존 로그인/세션과 ID 연결을 보존하면서 끊긴 연결을 수정하고 두 대상 전체 Recon을 동일 조건으로 비교한다.

1. 원본 변경을 보존한 소스 스냅샷으로 기본 정책(500회, 0.5 rps, 동시 1), common.txt, 기존 계정의 정상 로그인 기준선 실행.
2. ZAP 단계의 인증 전달과 생성 파라미터 문제 재현. 인증은 대상 origin에 한정해 전달하며 로그는 존재 여부만 기록.
3. 실제 HTML select/input와 명시적 GET JavaScript의 값 흐름을 연결하고 쿼리를 유지. JSON 응답 연결에서도 쿼리 템플릿을 지원. 근거 없는 값은 사용하지 않는다.
4. 경로 단위 Surface와 인증/파라미터별 검증을 분리. 기존 실패 관측은 인증된 실제 값 요청을 차단하지 않는다. 기존 요청/분석 상한 유지.
5. OpenAPI의 required GET 파라미터는 해당 경로의 실제 JS/DOM/요청 근거로만 채움. 스키마 예제/기본값으로 요청하지 않는다.
6. 일반 가상 앱의 회귀 검사를 먼저 실패시킨 후 구현. Scope·응답 대조·인증정보 비노출 검사 포함.
7. 수정 소스 스냅샷으로 동일 계정/데이터/설정의 개선 실행. 원시 HTTP·Surface·성공·신규/손실·보조 단계 실패를 별도 평가하고 한계를 보고.

평가 전에는 서버 소스/정답 목록을 읽어 발견을 유도하지 않는다. 데이터 생성/수정은 하지 않는다. 기존 미커밋 변경과 인증 세션 원본은 보존한다.
